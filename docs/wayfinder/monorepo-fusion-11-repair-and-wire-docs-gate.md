# monorepo-fusion-11 — Repair the docs gate and wire it into check

**Wayfinder:** `monorepo-fusion`
**Branch:** `task/monorepo-fusion-11-repair-and-wire-docs-gate`
**Status:** done · 2026-08-24

## Goal

Make `check-docs.mjs` correct against the merged bundle, then wire `check:docs` into
`check`. Read ADR 0056 — the gate was already run against claude's docs and its failures
are known exactly.

## What the measurement showed

codex's `check-docs.mjs`, pointed at claude-proxy's 62 documents, fails with **exactly
five errors**:

- **0 genuinely broken links.** claude's bundle is clean; link health was never the risk.
- **1 containment violation**: `docs/features/ideas-ledger.md` →
  `../../services/concepts/README.md`, a legitimate link out to source.
- **4 missing index assertions**: the script requires `docs/index.md` to contain the
  literal `(adrs/index.md)`, `(features/index.md)`, `(specs/index.md)`,
  `(roadmap/index.md)`.

The fourth is not what blocker (h) assumed. `docs/index.md` is **generated by okq**
between `okq:index:begin`/`okq:index:end` markers and emits **directory** links —
`[adrs/](adrs/)`. Adding the literal form by hand would be overwritten on the next okq
run. claude also has no `docs/roadmap/` (it arrives with ox) and does have a
`docs/wayfinder/` the assertion never checks.

## State changed under this plan — read before acting on its criteria

**Ticket 25 already deleted both `stacks/*/scripts/check-docs.mjs` and their `package.json`
wiring.** It was outside that ticket's declared lane and it said so, but the reasoning holds:
those scripts walked bundles that no longer exist and would have failed with `ENOENT`. So
there is now exactly one docs gate to repair, at the root, and **criterion 4's "create
`docs/index.md` for ox's bundle" is moot** — ox's bundle is gone, folded into the root by
ticket 25 along with codex's.

**The measured failure set is also different from what criterion 1 describes.** The current
`okq --bundle docs validate` baseline is **26 errors, all of them `docs/wayfinder/` plans
missing a `type` field** — pre-existing, and not what this ticket is about. Blocker (h)'s
original five errors against claude's 62 documents were measured before the corpus tripled.
**Re-measure before acting**, and do not "fix" the wayfinder plan errors: those files are
deleted wholesale by the `zz` ticket.

## Also in scope, added after ticket 13 landed

**Supersession in this corpus is discoverable only forward.** A record names what it
supersedes; **nothing names what supersedes it**, and no `superseded-by` key exists anywhere
in `docs/adrs/`. So a reader arriving at 0022, 0023 or 0028 has no way to learn that 0039
replaced them — they read as current. In a corpus this campaign just tripled in size, that is
a real navigation defect rather than a tidiness one.

- **Add a `superseded-by` frontmatter key** to every record that something supersedes. Derive
  the set from the existing forward `Supersedes` references rather than by hand — at minimum
  0022, 0023 and 0028, but scan for others rather than trusting that list.
- **Assert it in the gate**: for every `superseded-by: X`, record X must exist and must name
  this record in its own supersedes reference. **Bidirectional or it fails.** A one-way link
  is what produced this defect, and a gate that only checks the direction that already works
  would let it recur.
- **Do not mark anything superseded that is not.** The distinction ADR 0053 draws holds here:
  a *merged* record is not a superseded one, and the eight merged pairs must not acquire this
  key by association.

## Criteria

1. **Assert each section index exists as a file**, not that the root index links to it
   in a particular literal form: `existsSync(join(docsRoot, section, 'index.md'))`. That
   is what the assertion was reaching for; the string grep was a proxy okq's output does
   not satisfy.
2. **Relax containment to permit links that resolve to a tracked file in the
   repository**, and keep rejecting links that resolve nowhere. The distinction the rule
   should draw is between a link that works and one that does not — not between a doc
   inside `docs/` and one pointing at the source it documents. codex's version conflates
   them and reports a working link as an error.
3. **Derive the checked section list from the directories present**, not a hardcoded
   array. The merged bundle has `adrs/`, `features/`, `specs/`, `roadmap/` (from codex
   and ox) and `wayfinder/` (from claude). A hardcoded list is wrong for at least one
   stack in every arrangement.
4. **Create `docs/index.md` for ox's bundle content** — ox has **no `docs/index.md` at
   all**, which is why its rewrite dropped the assertion rather than fixing it.
5. **Keep codex's version as the base.** It has the containment check and the index
   assertion that ox's rewrite dropped; this ticket preserves both in intent.
6. **Only then wire `check:docs` into `check`** (`biome check . && pnpm check:docs`).
   Blocker (h) is explicit that the gate runs against claude's never-link-checked docs
   *before* it becomes a gate.
7. **Require `scope` on every doc**, not only ADRs, and make the docs index filterable
   by it. `scope: all` documents are the shared trunk every stack's check-docs
   validates. Add the `scope` assertion to this script.

## Done when

`pnpm check:docs` passes against the merged bundle, `check` chains it, every document in
the bundle carries a `scope`, and `okq --bundle docs validate` reports conformant.
